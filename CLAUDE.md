# CryptKill — TinyTapeout AES-128-XTS self-encrypting controller

Handoff/context file. Read this first. It is the single source of truth for
continuing this project in any fresh session (Claude Code or chat).

## What this chip is
A self-encrypting storage controller for TinyTapeout (open-source SKY130 ASIC).
It transparently encrypts every byte written to a commodity SPI-NOR flash under
a key held only on-die, and its headline feature is **hardware crypto-erase**:
a TAMPER pin zeroizes all key material within 2 clocks, so the flash contents
become permanently unrecoverable in microseconds. Target audience:
military / cyber data-at-rest. Framing: an honest, inspectable *demonstrator*
of key-binding + instant crypto-erase using standard AES — not a certified
product. Do NOT roll custom crypto; standard AES only.

## Locked spec
- Cipher/mode: **AES-128 in XTS mode** (IEEE 1619 / NIST SP 800-38E). Two
  128-bit keys (Key1 = data, Key2 = tweak) => 256 bits of key material.
- Tweak: `T0 = AES_enc(Key2, sector_number_as_128bit_LE)`; per 16-byte block
  multiply T by alpha in GF(2^128), reduction poly 0x87 (1-bit left shift,
  little-endian, XOR 0x87 into byte 0 on carry-out).
- No ciphertext stealing: fix the data unit (sector) to a multiple of 16 bytes.
- Storage: SPI NOR flash (W25Q-class), controller = SPI master.
- Host / test driver: RP2040 on the TT demo board drives the pins; key loaded
  via a protected command (UART-style) at power-up.
- Crypto-erase: a TAMPER input pin clears BOTH keys + all key-derived state (2 clk, sync).
- Device-bind (stretch, later): `effective_key = key XOR H(device_id)` where
  device_id is strapped on spare pins — deterministic, simulable. A real RO-PUF
  is a silicon-only upgrade path, never a demo dependency (can't verify pre-fab).
- Tiles: **4x2** (AES enc+decrypt + 256-bit key + XTS + SPI); chosen from the
  sky130 area estimate below. Shuttle: `ttsky-verilog-template`, TTSKY26d/26e (SKY130).
  Pace: opportunistic for the 2026-11-30 close, otherwise the next shuttle.
  Result > speed.

## Verification model (IMPORTANT)
- There is a **pure-Python golden model** at `model/aes_xts_ref.py`, verified
  bit-exact against FIPS-197 and IEEE-1619 XTS vectors. Treat it as ground truth
  for byte ordering and algorithm. All RTL is written to match it.
- Verilog is verified via **GitHub Actions CI** (`.github/workflows/aes.yaml`
  installs Icarus Verilog + cocotb and runs the tests). If you have a local
  simulator (iverilog + cocotb), run `make -C verify` locally too.
- cocotb tests live under `verify/` and check the RTL against the golden model
  (fixed KATs + randomized vectors).

## Status
- DONE: `src/aes128.v` — byte-serial AES-128, encrypt **and** decrypt, on-the-fly
  key schedule. One forward + one inverse LUT S-box shared by the whole datapath
  (state SubBytes 1 byte/clk with AddRoundKey fused, key schedule 1 byte/clk),
  one MixColumns column network (InvMixColumns = MixColumns(imc_pre(col))).
  Latency (start sample -> done read high): enc 248 clk, dec 289 clk (incl. a
  40-clk forward key setup to k10). Ports/handshake unchanged: `key`/`din`/`dec`
  latched at `start`; `start` edge-gated and ignored while busy; done+busy=0 on
  one edge; `dout` held until the next done. Generated by `tools/gen_aes.py`
  (`cd tools && PYTHONPATH=../model python3 gen_aes.py && mv aes128.v ../src/`);
  S-box/Rcon tables come from the golden model. Verified: FIPS KAT + 32 random
  enc/dec vectors + `test_aes_fsm_edges` (exact latency, inputs changed after
  start, start while busy, start held across done, back-to-back enc/dec), and all
  xts suites unchanged except timeouts. Mutation-checked: 10 injected FSM/datapath
  bugs all caught. Upgrade path: a shared composite-field S-box (GF((2^4)^2))
  would replace both LUTs.
- DONE: `src/xts128.v` — AES-128-XTS wrapper sharing one `aes128` core.
  `tweak_start` computes T = AES_enc(key2, bswap(sector)); each `blk_start`
  runs one block (`dec` selects direction), `done` pulses, `dout = aes_dout ^ T`
  held until the next block is accepted. T advances by alpha lazily at the next
  block accept (saves a 128-bit output register). Verified by `verify/xts_test.py`:
  IEEE-1619 #1/#2 enc+dec + 12 random sectors (1..32 blocks, full 128-bit seq)
  vs `xts_crypt`, plus a back-to-back test that starts each block on the cycle
  `busy` drops (the tweak result is bypassed into a block accepted that cycle).
- DONE: key registers + CRYPTO-ERASE (in `src/xts128.v`). Key1/Key2 live inside
  xts128; each clk with `key_wr` high (ignored while busy) shifts `key_byte` into
  {key1,key2}, so 32 writes load the 256-bit XTS key in IEEE-1619 order (key1
  byte 0 first) -- fits a byte-wide host protocol in TODO #4. `tamper` goes
  through a 2-FF synchronizer whose output drives the async reset of ONE erase
  domain (`rst_e = rst_n & ~tsync[1]`): key1, key2, T, the whole aes128 core
  (rk, st, dout, FSM) and all xts control state. Erased within 2 clk of tamper
  being sampled high, regardless of start/busy/mode; held while tamper is high
  (key loads ignored); the in-flight op is aborted (no done). Only the
  synchronizer flops are outside the domain. Verified by `test_xts_tamper_erase`:
  KAT before, tamper during a tweak / mid-block / late in a dec block, every
  secret register (key1, key2, T, core.rk/st/dout) reads 0, no done afterwards,
  the same ciphertext then decrypts to garbage (== decrypt under the all-zero
  key, != plaintext), key load ignored during tamper, reload restores the KAT.
  Mutation-checked: dropping any one of key1/key2/T/rk/st/dout from the erase,
  wiring the core to plain rst_n, or not wiring tamper -- all 8 caught, each
  naming the register left. LIMITS (hardened upgrade, later): erase needs a
  running clk and a tamper pulse >= 1 clk (synchronous sampling); a
  clock-independent async erase is the upgrade. Zeroing is a reset to 0, not a
  multi-pass overwrite; no protection against data remanence or power/probing
  attacks.
- DONE: `src/spi_nor.v` — SPI-NOR (W25Q) master, single-bit mode 0, SCK=clk/2.
  Ops: READ(03), PROGRAM(06|02+data|05 poll), ERASE4K(06|20|05 poll), NOP.
  Byte streams: wdata/wvalid/wready (wready pulses the cycle after the byte is
  taken), rdata/rvalid/rready (held). CS high >= 9 clk between commands.
  Caller must keep a PROGRAM inside one 256 B page (top-level check). No WIP
  timeout. Verified by `verify/spi_test.py` against a Python W25Q model that also
  checks the wire protocol (mode 0, byte-aligned CS, tSHSL, MOSI setup/hold, WEL,

  erase/program/read ops with backpressure + full readback, edge cases
  (len=0, NOP, held start, long WIP, back-to-back). Mutation-checked: 7 injected
  RTL bugs all caught. NOT verified: real pad/board timing (MISO round trip must
  fit in one clk; keep clk <= ~25 MHz until measured), real W25Q on FPGA.

- DONE: `src/tt_um_cryptkill.v` -- top. Pinout (also in info.yaml): ui[7:0] host
  byte; uio0 FLASH_CS_N, uio1 SCK, uio2 MOSI (out), uio3 MISO (in), uio4 HOST_VALID,
  uio5 HOST_CMD (in), uio6 ACK (out), uio7 TAMPER (in); uio_oe = 8'b0100_0111;
  uo = status {BUSY,0,0,ERASING,FULL,ERR,SEC_OK,KEY_OK}, or plaintext bytes during
  READ_BLOCK output. Host protocol: 4-phase byte handshake (VALID up -> ACK up
  when the byte AND any flash/AES work it started is done -> VALID down -> ACK
  down); HOST_VALID is 2-FF synchronized, ui/HOST_CMD must be stable while VALID
  is high. Commands 01 LOAD_KEY+32B (idle only; clears KEY_OK+SEC_OK, so a
  mid-sector key change forces SET_SECTOR), 02 SET_SECTOR+2B (15-bit n, needs
  KEY_OK; flash addr n*512), 03 WRITE_BLOCK+16B, 04 READ_BLOCK (16 output
  handshakes), 05 ERASE (4 KB holding n, needs SEC_OK). Block ops need SEC_OK and
  j<32, sequential within a 512 B sector. Rejected bytes are ACKed and set ERR.
  The whole top (FSM, 128-bit block buffer, flags, SPI master) is in the erase
  domain (rst_e from xts128's `erasing`); only the VALID and TAMPER synchronizers
  are outside. No new register holds key material (key bytes go ui -> xts key
  shift register combinationally). Verified by `test/test.py` (cocotb 2.1, pins
  only, RTL + GL): key load, ERASE, full 32-block sector write, flash contents ==
  `xts_crypt` ciphertext, readback == plaintext, protocol guards (no key, mid-sector
  key load, 33rd block, unknown cmd, stray data, cmd mid-data), TAMPER mid-READ
  (secrets incl. buf_q == 0 in RTL, status 0, CS high), then refused, wrong key ->
  garbage == model decrypt, correct key -> plaintext again. GL run uses 2 blocks.
  Mutation-checked: 10 top-level bugs all caught. Verilator -Wall lint clean.
  The flash model now ends a transaction when CS rises during tCLQV (a tamper
  reset raises CS and drops SCK on the same edge).

## Conventions
- Keep all S-box / algorithm constants sourced from the golden model — never
  hand-type crypto tables.
- Byte order in RTL: `din[127:120]` = byte 0; AES state is column-major,
  column c = bits `[(3-c)*32 +: 32]`, `state[c*4+r]` = byte `c*4+r`.
- One verifiable block per commit; CI must stay green on `aes-core-test`.
